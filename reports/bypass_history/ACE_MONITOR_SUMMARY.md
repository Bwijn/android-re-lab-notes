# 🛡️ 腾讯 ACE 监控与扫描机制深度总结 (Technical Summary)

**目标对象**: `libtersafe.so`, `libTDataMaster.so`
**对抗等级**: Tier 1 (Industrial Grade)

---

## 1. 文件系统探测 (Filesystem Probing)
ACE 会通过 `openat` 和 `access` 系统调用高频扫描以下路径，判定是否存在 Root 或劫持环境：

*   **Root 特征**: 
    *   `/system/bin/su`, `/system/xbin/su`
    *   `/data/adb` (Magisk/KernelSU 的核心目录)
    *   `/sbin/.magisk/`, `/dev/.magisk/`
*   **注入框架特征**:
    *   `/data/local/tmp/re.frida.server`
    *   `/data/local/tmp/re.zyg.fri/` (Zygisk-Frida 的配置文件)
*   **运行时元数据 (Runtime Metadata)**:
    *   `/proc/self/maps`: 核心扫描对象，寻找异常的 `.so` 映射。
    *   `/proc/self/status`: 重点读取 `TracerPid` 字段，判定是否被附加了调试器。
    *   `/proc/self/mounts`: 检测是否存在 `mount --bind` 的挂载隐藏行为。

## 2. 内存特征扫描 (Memory Scanning)
ACE 不仅看文件名，还会直接深入内存读取字节码：

*   **String Pattern Match (字符串匹配)**:
    *   在所有的 `r--` 或 `r-x` 段搜索 "frida", "gum-js-loop", "frida:rpc" 等硬编码字符串。
*   **In-line Hook Detection (内联钩子检测)**:
    *   **Checksum 校验**: ACE 会计算 `libc.so` 中关键函数（如 `openat`, `read`, `write`, `ptrace`）的前 16 字节哈希值。如果发现开头变成了 `LDR` 或 `BR` 指令（Frida 的跳转特征），立刻触发检测。
*   **Module Validation**:
    *   验证 `libil2cpp.so` 的内存校验和，防止玩家修改代码段实现“秒杀”等功能。

## 3. 运行环境与系统属性 (System Environment)
通过 `__system_property_get` 接口读取安卓全局属性：

*   **Debug 状态**: `ro.debuggable` (如果是 1，直接判为风险环境)。
*   **安全状态**: `ro.secure` (判定内核是否开启了安全校验)。
*   **USB 调试**: 检测 `adb_enabled` 状态。
*   **开发者选项**: 监控是否开启了“模拟位置”或“辅助点击”服务。

---

## 4. 主动防御行为 (Active Defense Behavior)

*   **Syscall Bypass (系统调用绕过)**:
    为了对抗像我们刚才那样的 `libc` Hook，ACE 的高级版本会直接在汇编层使用 `SVC 0` 指令发起系统调用。这种方式**完全不经过 libc.so**，导致我们的 Frida 脚本“失聪”。
*   **Thread Enumeration (线程枚举)**:
    ACE 会调用 `pthread_getcpuclockid` 或遍历 `/proc/self/task`，寻找那些没有在游戏名单里的“流氓线程”（Frida 会创建数个维护通信的背景线程）。
*   **Delayed Punishment (延迟惩罚)**:
    ACE 并不总是在发现问题时立即闪退。它会将检测结果加密后，通过网络通道发送给 `nj.cschannel.anticheatexpert.com`。服务端确认后，可能会在几分钟甚至几天后下发封号指令。

## 5. 针对性防御 (Defense/Bypass Strategy)

要过 ACE，传统的 Hook 已经不够了，必须使用 **“透明化”** 技术：

1.  **Kernel-level Masking (内核级掩码)**:
    利用 **KernelSU** 在内核层拦截文件读取请求，自动过滤 Frida 痕迹。
2.  **Syscall Hooking (系统调用挂钩)**:
    使用 `seccomp` 拦截原始系统调用号。
3.  **Hardware Breakpoint (硬件断点)**:
    使用 CPU 寄存器监控内存，规避 Checksum 检测。
